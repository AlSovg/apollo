# ADR — архитектурные решения

Architecture Decision Records: короткая фиксация решения, альтернатив и
причины отказа от них — чтобы на защите и через полгода не пересказывать
дискуссию по памяти. Меняется решение — не правим старую запись, а добавляем
новую со статусом `Заменена ADR-000N`.

Нумерация сквозная, статусы: `Предложена` / `Принята` / `Заменена` / `Отклонена`.

| № | Заголовок | Статус |
|---|---|---|
| [0001](0001-postgres-queue.md) | Очередь на PostgreSQL, не брокер сообщений | Принята |
| [0002](0002-worker-scaling.md) | Горизонтальное масштабирование воркеров через `SKIP LOCKED` | Принята |
| [0003](0003-load-balancing.md) | Балансировка — nginx + Docker DNS, не выделенный LB | Принята |
| [0004](0004-db-scaling.md) | Масштабирование БД — потоковая репликация, не шардирование | Принята |
| [0005](0005-orchestration.md) | Оркестрация кластера — Compose/Swarm, не Kubernetes | Принята |
| [0006](0006-two-node-topology.md) | Два узла: БД отдельно от приложения, связь — оверлейная сеть | Принята |

См. также `docs/architecture-scaling.md` — итоговая схема, статус реализации
(что измерено, что целевая схема) и таблица соответствия требованиям задания.
