# Подключение языковой модели

> **Стенд без ВМ с моделью.** ВМ с Qwen3 сейчас недоступна, поэтому по
> умолчанию `LLM_PROVIDER=template`: сводку строит детерминированный шаблон
> (`backend/app/adapters/llm/template.py`) — он разбирает контекст инцидента
> (правило, объект, группу, критичность, ленту событий с метриками), считает
> динамику показателя и подставляет подсказку «чем грозит / что проверить» по
> ключевым словам правила. Результат воспроизводим и не требует сети. Всё, что
> ниже про vLLM и Qwen3, относится к `LLM_PROVIDER=openai`.

Модель используется ровно для одного — сводки инцидента для дежурного
(FR-AI-1..7). Нормализация, дедупликация, критичность и маршрутизация к ней
не обращаются: это детерминированный код.

## Контур

| | |
|---|---|
| Сервер | vLLM 0.9.2 на выделенной ВМ, OpenAI-совместимый API |
| Эндпоинт | `http://212.233.74.7:8000` (путь `/v1/chat/completions` дописывает клиент) |
| Модель | `qwen3-14b` — Qwen3-14B-AWQ, 4 бита, контекст 8192 токена |
| Железо | NVIDIA Tesla T4, 15 ГБ VRAM |
| Аутентификация | ключ в заголовке `Authorization: Bearer` |

Смена сервера или модели — это переменные окружения, код не меняется:
`LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` (см. `.env.example`).

Мок `llm-mock` из dev-оверлея остаётся: он повторяет тот же контракт и нужен
тестам и работе без ВМ.

## Особенности Qwen3, учтённые в коде

**Блок рассуждений.** Qwen3 — гибридная reasoning-модель: по умолчанию она
сначала пишет `<think>…</think>` и тратит на это секунды и токены. Клиент шлёт
`chat_template_kwargs: {"enable_thinking": false}` (`LLM_DISABLE_THINKING`).
На случай сервера, который это поле игнорирует, ответ дополнительно чистится:
закрытый блок вырезается, незакрытый (ответ упёрся в `max_tokens` прямо в
рассуждениях) считается пустым ответом и уводит вызов в повтор.

**Латентность.** T4 не поддерживает bfloat16 и FP8, поэтому скорость около
15 токенов/с: сводка занимает 6–8 секунд. Отсюда `LLM_TIMEOUT_S=60` вместо 30.

**Размер пачки.** Пачка обрабатывается одной транзакцией, поэтому
`LLM_BATCH_SIZE=5`: при 20 инцидентах блокировки висели бы больше двух минут,
а рестарт воркера выбрасывал бы всю незакоммиченную пачку.

**JSON по схеме не используется.** Всё машиночитаемое (критичность, объект,
признак теста) уже разобрано нормализатором до вызова модели, а structured
outputs на этом сервере втрое медленнее свободного текста. Модель отдаёт
обычный текст — ровно то, что показывается в карточке.

## Что модель не ломает

Сводка — содержимое уведомления, но не точка отказа. Доставка ждёт её до 15 с
и при таймауте отправляет уведомление с исходным сообщением инцидента.
Недоступность ВМ не задерживает приём события и задерживает уведомление не
больше чем на 15 с: воркер `llm` живёт отдельным процессом. В коде ожидание
пока не реализовано (`docs/tz.md`, FR-AI-4).

## Открытые вопросы безопасности

- API отдаётся по HTTP без TLS — ключ уходит по сети открытым. Для боевого
  контура нужен TLS, это часть обвязки ИБ (шаг 13).
- Порт 8000 на ВМ открыт наружу, защита только ключом. Ограничение по адресу
  источника или SSH-туннель снимают вопрос.
- В логи попадает только `incident_id` и латентность; текст контекста и ответа
  не логируются (требование по ПДн из `AGENTS.md`).
